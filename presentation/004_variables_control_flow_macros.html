Part 1

Variables

Mutability

let mut score = 0;
println!("{score}");
score = 10;
score += 5;
println!("{score}");
Output 
0
15
  • let mut lets a variable get a new value later.
  • +=, -=, *=, /= update a variable in place.
  • Without mut, a value can never change. You saw the error for that in chapter 2.
  • Immutable by default means you can see at a glance which values change.

What mut doesn't do

Constants

const MAX_POINTS: u32 = 100_000;
const SECONDS_IN_HOUR: u32 = 60 * 60;

fn main() {
    println!("{MAX_POINTS} {SECONDS_IN_HOUR}");
}
error: missing type for `const` item
 --> src/main.rs:1:17
  |
1 | const MAX_POINTS = 100_000;
  |                 ^ help: provide a type for the constant: `: i32`
  • const declares a value that never changes.
  • The type is required. Constants have no type inference.
  • The value is computed at compile time.
  • Constants can be declared outside functions and are named in SCREAMING_SNAKE_CASE.
  • static also exists, for a value with one fixed place in memory. You'll rarely need it.

Shadowing

let spaces = "   ";
let spaces = spaces.len();
println!("{spaces}");

let level = 1;
{
    let level = level * 2;
    println!("inner: {level}");
}
println!("outer: {level}");
Output 
3
inner: 2
outer: 1
  • A second let with the same name creates a new variable that hides the old one.
  • The new variable can have a different type: &str becomes usize.
  • Shadowing inside a block ends at }, and the outer variable is visible again.

Part 2

Control flow

if, else if, else

let temperature = 18;
if temperature < 10 {
    println!("cold");
} else if temperature < 20 {
    println!("mild");
} else {
    println!("warm");
}
Output 
mild
  • No parentheses around the condition. The braces are required.
  • Conditions are checked from the top, and only the first matching branch runs.
  • Comparisons: ==, !=, <, <=, >, >=. Logic: &&, ||, !.

The condition must be a bool

error[E0308]: mismatched types
 --> src/main.rs:3:8
  |
3 |     if number {
  |        ^^^^^^ expected `bool`, found integer
  • Rust has no "truthy" values. A number, a string or an array is never treated as true or false.
  • Write the comparison you mean: if number != 0.

if is an expression

let label = if temperature < 20 { "cool" } else { "warm" };
error[E0308]: `if` and `else` have incompatible types
 --> src/main.rs:3:55
  |
3 |     let label = if temperature < 20 { "cool" } else { 20 };
  |                                       ------          ^^ expected `&str`, found integer
  |                                       |
  |                                       expected because of this
  • if produces a value, just like a block (chapter 2). It replaces the ? : operator from other languages.
  • Both branches must have the same type, because label has a single type.

Returning early

fn describe(number: i32) -> &'static str {
    if number < 0 {
        return "negative";
    }
    if number == 0 {
        return "zero";
    }
    "positive"
}
  • return leaves the function at once. This is its main use, promised in chapter 2.
  • Handle the special cases first, then write the main case as the last expression.
  • The return type &'static str comes from chapter 3: string literals live for the whole program.

loop

let mut counter = 0;
let result = loop {
    counter += 1;
    if counter == 10 {
        break counter * 2;
    }
};
println!("{result}");
Output 
20
  • loop repeats forever, until break.
  • break value stops the loop and makes the loop produce that value.
  • continue skips the rest of the body and starts the next round.

while

let mut countdown = 3;
while countdown > 0 {
    println!("{countdown}...");
    countdown -= 1;
}
println!("liftoff!");
Output 
3...
2...
1...
liftoff!
  • while checks the condition before each round.
  • It stops as soon as the condition is false.
  • Like if, the condition must be a bool.

for

for number in 1..=3 {
    print!("{number} ");
}
for number in (1..=3).rev() {
    print!("{number} ");
}
let primes = [2, 3, 5, 7, 11];
for prime in primes {
    print!("{prime} ");
}
Output 
1 2 3 3 2 1 2 3 5 7 11
  • 1..=3 includes 3. 0..3 stops before 3: 0 1 2.
  • .rev() goes backwards.
  • for over an array visits each element. There's no index to get wrong, so it can't go out of bounds.
  • for is the loop you'll use most.

Iterators in general, slices and Vec are covered in chapter 5.

Loop labels

'outer: for row in 1..=3 {
    for column in 1..=3 {
        if row * column == 4 {
            break 'outer;
        }
        println!("{row} x {column} = {}", row * column);
    }
}
Output 
1 x 1 = 1
1 x 2 = 2
1 x 3 = 3
2 x 1 = 2
  • break and continue affect the innermost loop.
  • A label such as 'outer lets you break out of an outer loop.
  • The ' looks like a lifetime from chapter 3, but a label is just a name for a loop.

match

let dice = 4;
let message = match dice {
    1 => "one",
    2 | 3 => "two or three",
    4..=6 => "four to six",
    _ => "not a dice value",
};
println!("{message}");
Output 
four to six
  • Each arm is a pattern, then =>, then the result.
  • Arms are checked from the top, and the first match wins.
  • | means "or", 4..=6 is a range, and _ matches anything.
  • match is an expression, like if.

match must cover every value

error[E0004]: non-exhaustive patterns: `i32::MIN..=0_i32` and `7_i32..=i32::MAX` not covered
 --> src/main.rs:3:25
  |
3 |     let message = match dice {
  |                         ^^^^ patterns `i32::MIN..=0_i32` and `7_i32..=i32::MAX` not covered
  |
  = note: the matched value is of type `i32`
  • Without the _ arm, the compiler lists exactly which values aren't handled.
  • Its help: suggests adding an arm for them, or a _ arm.
  • This check is what makes match so useful with enums and Option in chapter 5.
Part 3

Macros

Code that writes code

What is a macro?

Expanded at compile time

A macro call is replaced by the code it generates before the program is compiled further. The ! marks a macro call.

Any number of arguments

A function has a fixed list of parameters. println! takes one argument, or five.

Checked during compilation

The format string is checked against the arguments before the program runs:

error: 2 positional arguments in format string, but there is 1 argument
 --> src/main.rs:2:15
  |
2 |     println!("{} {}", 1);
  |               ^^ ^^   -

Standard macros

MacroWhat it does
print!, println!Print to standard output, without and with a newline
eprint!, eprintln!Print to standard error, for errors and diagnostics
format!Build a String using the same placeholders
dbg!Print an expression, its value, file and line to standard error, then return the value
panic!, todo!, unreachable!Stop the program with a message
assert!, assert_eq!Panic if a condition doesn't hold. Used in tests (chapter 6).
vec!Create a Vec (chapter 5)

format!, eprintln!, dbg!

let name = "Ferris";
let greeting = format!("Hello, {name}!");
eprintln!("warning: {greeting}");
let doubled = dbg!(21 * 2);
println!("{doubled}");
Standard error 
warning: Hello, Ferris!
[src/main.rs:5:19] 21 * 2 = 42
Standard output 
42
  • format! returns the text as a String instead of printing it.
  • Standard error is a separate stream: cargo run 2>errors.txt moves it into a file.
  • dbg! shows where and what, then hands the value back, so you can wrap any expression in it.

Stopping the program

fn next_level(level: u32) -> u32 {
    match level {
        1 | 2 => level + 1,
        3 => todo!("the final level"),
        _ => unreachable!("only levels 1 to 3 exist"),
    }
}

Writing a macro

macro_rules! square {
    ($value:expr) => {
        $value * $value
    };
}

println!("{}", square!(7));
println!("{}", square!(1 + 2));
Output 
49
9
  • macro_rules! defines a macro. Each rule is a pattern, =>, and the code to generate.
  • $value:expr matches any expression and names it $value.
  • square!(1 + 2) is 9, not 5: the macro works on whole expressions, not on text.

Repetition

macro_rules! sum {
    ($($value:expr),*) => {
        0 $(+ $value)*
    };
}

println!("{}", sum!(1, 2, 3));
println!("{}", sum!());
Output 
6
0
  • $( … ),* matches the pattern zero or more times, separated by commas.
  • $( … )* in the generated code repeats once for each match.
  • sum!(1, 2, 3) becomes 0 + 1 + 2 + 3.

Macro or function?

Prefer a function

  • Its signature documents and checks the types.
  • Compiler errors are clearer.
  • It's easier to read, test and document.

Use a macro when you need

  • a variable number of arguments
  • checks at compile time, like format strings
  • to generate repetitive code you can't write as a function

You'll use macros every day, but write your own much less often.

Summary

  • mut allows new values of the same type. const needs a type and never changes.
  • Shadowing creates a new variable with the same name and can change the type.
  • if and match are expressions. Conditions must be bool, and match must cover every value.
  • loop repeats until break, while checks a condition, and for walks ranges and arrays.
  • Macros expand at compile time: printing, formatting, dbg!, and todo! and other panics.
  • macro_rules! defines macros with patterns and repetition.

Sterowanie przepływem

if, else if, else

Makra

Kod, który pisze kod

Czym jest makro?

Rozwijane w czasie kompilacji

Wywołanie makra jest zastępowane wygenerowanym kodem, zanim program zostanie dalej skompilowany. ! oznacza wywołanie makra.

Dowolna liczba argumentów

Funkcja ma stałą listę parametrów. println! przyjmie jeden argument albo pięć.

Sprawdzane podczas kompilacji

Napis formatujący jest porównywany z argumentami, zanim program zostanie uruchomiony:

  • $( … ),* dopasowuje wzorzec zero lub więcej razy, oddzielony przecinkami.
  • $( … )* w generowanym kodzie powtarza się raz dla każdego dopasowania.
  • sum!(1, 2, 3) zmienia się w 0 + 1 + 2 + 3.

Makro czy funkcja?

Wybieraj funkcję

  • Jej sygnatura dokumentuje i sprawdza typy.
  • Błędy kompilatora są czytelniejsze.
  • Łatwiej ją czytać, testować i dokumentować.

Użyj makra, gdy potrzebujesz

  • zmiennej liczby argumentów
  • sprawdzania w czasie kompilacji, np. napisów formatujących
  • generowania powtarzalnego kodu, którego nie da się zapisać jako funkcji

Makr będziesz używać codziennie, ale własne pisać znacznie rzadziej.

Podsumowanie

  • mut pozwala na nowe wartości tego samego typu. const wymaga typu i nigdy się nie zmienia.
  • Przesłanianie tworzy nową zmienną o tej samej nazwie i może zmienić typ.
  • if i match to wyrażenia. Warunki muszą być typu bool, a match musi obsłużyć każdą wartość.
  • loop powtarza aż do break, while sprawdza warunek, a for przechodzi po zakresach i tablicach.
  • Makra rozwijają się w czasie kompilacji: wypisywanie, formatowanie, dbg!, a także todo! i inne panic.
  • macro_rules! definiuje makra za pomocą wzorców i powtórzeń.

Dalej: rozdział 5, struktury danych i typy złożone.
