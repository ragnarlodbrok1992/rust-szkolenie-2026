Part 1

Tuples, arrays, and slices

Destructuring

let person = ("Alice", 30, 1.68);
let (name, age, _) = person;
println!("{name} is {age}");

let (smallest, largest) = min_max(9, 4);
println!("{smallest} {largest}");

fn min_max(first: i32, second: i32) -> (i32, i32) {
    if first < second {
        (first, second)
    } else {
        (second, first)
    }
}
Output 
Alice is 30
4 9
  • A pattern on the left of let unpacks a tuple into variables.
  • _ skips a field you don't need.
  • The pattern must have exactly as many fields as the tuple (E0308 otherwise).
  • Returning a tuple is how a function returns several values.

Slices

let primes = [2, 3, 5, 7, 11];
let middle = &primes[1..4];
println!("{middle:?} {}", middle.len());
Output 
[3, 5, 7] 3
  • A slice borrows a run of neighboring elements without copying them.
  • It stores a pointer to the first element and a length.
  • Its type is &[i32]. Ranges: [1..4], [..2], [3..], [..].

Slices as parameters

fn sum(numbers: &[i32]) -> i32 {
    let mut total = 0;
    for number in numbers {
        total += number;
    }
    total
}

println!("{}", sum(&primes));
println!("{}", sum(&primes[..2]));
Output 
28
5
  • A &[i32] parameter accepts a whole array, a part of it, or a Vec.
  • A range outside the data panics:
range end index 10 out of range
for slice of length 5

String slices

let text = String::from("hello world");
let hello = &text[0..5];
let world = &text[6..];
println!("{hello} | {world}");
Output 
hello | world
  • &str is a string slice: a pointer and a length into some text.
  • A string literal is a slice of text stored in the program binary (chapter 3).
  • The range counts bytes, not characters. More in part 2.
Part 2

Collections

Vec, String, HashMap, iterators, and closures

Vec: a growable list

let mut scores = Vec::new();
for round in 1..=3 {
    scores.push(round * 10);
}
let mut letters = vec!['a', 'b', 'c'];
let last = letters.pop();
println!("{scores:?} {letters:?} {last:?}");
Output 
[10, 20, 30] ['a', 'b'] Some('c')
  • Vec<T> keeps its elements on the heap, like String: pointer, length, capacity.
  • Read <T> as "of type T": Vec<i32>. Generics are covered in chapter 6.
  • vec![…] creates a Vec with elements. push and pop need mut.
  • pop returns an Option, because the Vec may be empty (part 4).

Reading elements

println!("{}", scores[1]);
println!("{:?}", scores.get(1));
println!("{:?}", scores.get(10));
Output 
20
Some(20)
None
scores[10] 
index out of bounds: the len is 3 but the index is 10
  • [index] panics when the index is too big.
  • .get(index) never panics. It returns Some(value) or None.
  • Use [ ] when the index is surely valid, and .get() when it might not be.

Iterating and changing elements

for score in &scores {
    print!("{score} ");
}
for score in &mut scores {
    *score += 1;
}
println!("{scores:?}");
Output 
10 20 30 [11, 21, 31]
  • for score in &scores borrows each element to read it.
  • &mut scores borrows each element to change it.
  • *score dereferences: it means the value the reference points to.
  • for score in scores, without &, moves the Vec into the loop, and it can't be used afterwards.

A Vec and the borrowing rule

error[E0502]: cannot borrow `numbers` as mutable because it is also borrowed as immutable
 --> src/main.rs:4:5
  |
3 |     let first = &numbers[0];
  |                  ------- immutable borrow occurs here
4 |     numbers.push(4);
  |     ^^^^^^^^^^^^^^^ mutable borrow occurs here
5 |     println!("{first}");
  |                ----- immutable borrow later used here
  • first borrows an element, and push needs to change the whole Vec.
  • It's the borrowing rule from chapter 3. The next slide shows why it matters here.

Why: push can move the data

  • vec![1, 2, 3] has room for exactly 3 elements.
  • push(4) allocates a bigger buffer (capacity 6), copies the elements, and frees the old one.
  • first would still point to the freed memory. The borrow checker rejects this at compile time.

String in depth

let mut greeting = String::from("Hello");
greeting.push(',');
greeting.push_str(" world");
let full = format!("{greeting}!");
println!("{full}");
Output 
Hello, world!
  • A String is a growable list of bytes that always holds valid UTF-8 text.
  • push adds one char, and push_str adds a &str.
  • format! builds a new String from several pieces.

Bytes and characters

let word = "zażółć";
println!("{} {}", word.len(), word.chars().count());
Output 
10 6
  • In UTF-8 a character takes 1 to 4 bytes. ż, ó, ł, ć take 2 each.
  • .len() counts bytes, and .chars() walks the characters.
  • A byte position isn't necessarily a character, so strings can't be indexed.
word[0] 
error[E0277]: the type `str` cannot be indexed by `{integer}`
&word[0..3] 
byte index 3 is not a char boundary; it is inside 'ż' (bytes 2..4) of `zażółć`

Closures

let double = |x| x * 2;
let add = |a: i32, b: i32| a + b;
let offset = 10;
let shift = |x| x + offset;
println!("{} {} {}", double(4), add(2, 3), shift(1));
Output 
8 5 11
  • A closure is a function without a name: parameters between | |, then the body.
  • Parameter and return types are usually inferred.
  • A closure can use variables from around it, like offset.
  • You'll mostly pass closures to iterator methods.

Iterators

let numbers = [1, 2, 3, 4];
let doubled: Vec<i32> = numbers.iter().map(|n| n * 2).collect();
let total: i32 = numbers.iter().sum();
let words = ["apple", "fig", "banana"];
let long_count = words.iter().filter(|word| word.len() > 3).count();
for (index, word) in words.iter().enumerate() {
    println!("{index}: {word}");
}
Values and output 
doubled: [2, 4, 6, 8]  total: 10  long_count: 2
0: apple
1: fig
2: banana
  • .iter() borrows each element, and .iter_mut() borrows it mutably.
  • Adapters (.map(), .filter(), .enumerate()) build a new iterator. Consumers (.sum(), .count(), .collect(), for) run it.

Iterators are lazy

Without a consumer 
warning: unused `Map` that must be used
 --> src/main.rs:3:5
  |
3 |     numbers.iter().map(|n| n * 2);
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  = note: iterators are lazy and do nothing unless consumed
collect without a type 
error[E0283]: type annotations needed
 --> src/main.rs:3:9
  |
3 |     let doubled = numbers.iter().map(|n| n * 2).collect();
  |         ^^^^^^^                                 ------- type must be known at this point

.collect() needs to know which collection to build: let doubled: Vec<_>. The _ lets the compiler fill in the element type.

HashMap

use std::collections::HashMap;

let mut ages = HashMap::new();
ages.insert("Alice", 30);
ages.insert("Bob", 25);
println!("{:?}", ages.get("Alice"));
println!("{:?}", ages.get("Carol"));
Output 
Some(30)
None
  • A HashMap<K, V> stores values under keys.
  • use brings it into scope from the standard library.
  • insert adds a value, or replaces the old one for that key.
  • get returns an Option, and ages["Carol"] panics: no entry found for key.
  • Iterating goes in no particular order.

Counting with entry

let sentence = "the cat and the hat";
let mut counts = HashMap::new();
for word in sentence.split_whitespace() {
    let count = counts.entry(word).or_insert(0);
    *count += 1;
}
println!("{}", counts["the"]);
Output 
2
  • entry(word) finds the place for a key.
  • .or_insert(0) puts 0 there if the key is new, and returns a mutable reference to the value.
  • *count += 1 changes the value through that reference, like *score before.
Part 3

Structs

Named fields that belong together

Defining a struct

struct User {
    name: String,
    age: u32,
    active: bool,
}

let user = User {
    name: String::from("Alice"),
    age: 30,
    active: true,
};
println!("{} {}", user.name, user.age);
  • A struct names its fields and their types. An instance must set every field.
  • Fields are read with .name.
  • The struct owns its fields, and they're dropped together with it.

Changing and building structs

let mut user = User {
    name: String::from("Alice"),
    age: 30,
    active: true,
};
user.age += 1;
  • The whole instance is mut or not. Single fields can't be.
  • Without mut: E0594 cannot assign to user.age, as user is not declared as mutable.
fn new_user(name: String, age: u32) -> User {
    User {
        name,
        age,
        active: true,
    }
}
  • Field init shorthand: name instead of name: name, when a variable has the field's name.

Printing a struct

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

println!("{user:?}");
println!("{user:#?}");
Output 
User { name: "Alice", age: 30, active: true }
User {
    name: "Alice",
    age: 30,
    active: true,
}
  • #[derive(Debug)] generates the code that makes {:?} work for your type.
  • A type without it can't use {:?}, e.g. Meters on the next slide: E0277 Meters doesn't implement Debug.
  • How derive works is covered with traits in chapter 6.

Tuple structs

struct Meters(f64);
struct Seconds(f64);

let distance = Meters(5.0);
let time = Seconds(2.0);
println!("{}", distance.0 / time.0);
Output 
2.5
  • A tuple struct has a name, but its fields don't: .0, .1.
  • Meters and Seconds are different types, so you can't pass one where the other is expected, even though both hold an f64.

Methods

impl User {
    fn greeting(&self) -> String {
        format!("Hi, I'm {}", self.name)
    }

    fn birthday(&mut self) {
        self.age += 1;
    }
}

let mut user = User::new("Alice", 30);
user.birthday();
println!("{} ({})", user.greeting(), user.age);
Output 
Hi, I'm Alice (31)
  • An impl block adds functions to a type.
  • A method takes self first, and you call it with a dot: user.birthday().
  • &self borrows to read, and &mut self borrows to change, as in chapter 3.

Associated functions and self

impl User {
    fn new(name: &str, age: u32) -> Self {
        Self {
            name: String::from(name),
            age,
            active: true,
        }
    }

    fn into_name(self) -> String {
        self.name
    }
}
First parameterMeaning
&selfBorrows to read
&mut selfBorrows to change
selfTakes ownership. The instance is used up.
noneAssociated function, called as User::new(…)

Self means the type of the impl block, here User. new is the usual name for a constructor.

Lifetimes in structs

struct Excerpt<'a> {
    text: &'a str,
}
let novel = String::from("Call me Ishmael. Some years ago...");
let first_sentence = &novel[..16];
let excerpt = Excerpt {
    text: first_sentence,
};
println!("{}", excerpt.text);
  • A struct that holds a reference needs a lifetime, completing chapter 3.
  • Excerpt<'a> says: an excerpt can't outlive the text it borrows.
  • Prefer owned fields (String) unless you have a reason to borrow.

Part 4

Enums and Option

A value that is one of several variants

Enums

enum Shape {
    Circle(f64),
    Rectangle(f64, f64),
    Empty,
}

impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle(radius) => PI * radius * radius,
            Shape::Rectangle(width, height) => width * height,
            Shape::Empty => 0.0,
        }
    }
}
  • An enum value is exactly one of its variants.
  • A variant can carry data, like Circle(f64), or none, like Empty.
  • match picks the variant and takes its data out into variables.
  • Enums can have methods too.

PI is std::f64::consts::PI.

match must cover every variant

error[E0004]: non-exhaustive patterns: `&Shape::Empty` not covered
 --> src/main.rs:8:11
  |
8 |     match shape {
  |           ^^^^^ pattern `&Shape::Empty` not covered
  |
note: `Shape` defined here
 --> src/main.rs:1:6
  |
1 | enum Shape {
  |      ^^^^^
...
4 |     Empty,
  |     ----- not covered
  • The compiler names the exact variant that's missing.
  • Add a variant to an enum, and every match that forgets it stops compiling.

Option: a value or nothing

enum Option<T> {
    None,
    Some(T),
}
  • Rust has no null. A value that may be missing has the type Option.
  • You've already met it: checked_add (chapter 2), Vec::get, pop, HashMap::get.
  • An Option<i32> isn't an i32. You have to handle None before using the value.
let values = [10, 20, 30];
match values.get(5) {
    Some(value) => println!("found {value}"),
    None => println!("nothing there"),
}
Output 
nothing there

if let and helpers

if let Some(first) = values.first() {
    println!("first: {first}");
}
let bonus = 250_u8.checked_add(10).unwrap_or(0);
let fallback = letters.pop().unwrap_or('?');
Output and values 
first: 10
bonus: 0  fallback: 'b'
values.get(5).unwrap() 
called `Option::unwrap()` on a `None` value
  • if let handles one variant and ignores the rest.
  • .unwrap_or(default) gives the value, or the default for None.
  • .unwrap() gives the value or panics. Use it only when None really can't happen.

Result, for operations that can fail, is covered in chapter 6.

Choosing a data structure

TypeUse it forExample
TupleA few values of different types, by positionReturning (smallest, largest)
ArrayA fixed number of values of one type[i32; 5]
SliceBorrowing part of an array, Vec, or textParameters &[T], &str
Vec, StringLists and text that growScores, user input
HashMapLooking values up by keyWord counts
StructNamed fields that belong togetherA user
EnumA value that is one of several variantsA shape, Option

Summary

  • Destructuring unpacks tuples. Slices borrow part of an array, a Vec, or a string.
  • Vec, String, and HashMap grow on the heap and follow the borrowing rules.
  • A String is UTF-8: .len() counts bytes, and indexing isn't allowed.
  • Closures and iterator adapters process collections. Nothing happens until a consumer runs.
  • Structs group named fields. impl adds methods with &self, &mut self, or self.
  • Enums hold one of several variants. Option replaces null, and match must cover every case.

Krotki, tablice i wycinki

Destrukturyzacja

let person = ("Alice", 30, 1.68);

let (smallest, largest) = min_max(9, 4);
println!("{smallest} {largest}");

fn min_max(first: i32, second: i32) -> (i32, i32) {

    } else {
        (second, first)
    }
}
Wynik 
Alice is 30
4 9
  • Wzorzec po lewej stronie let rozpakowuje krotkę do zmiennych.
  • _ pomija pole, które nie jest potrzebne.
  • Wzorzec musi mieć dokładnie tyle pól, co krotka (inaczej E0308).
  • Zwrócenie krotki to sposób na zwrócenie kilku wartości z funkcji.

Wycinki (slices)

let primes = [2, 3, 5, 7, 11];
let middle = &primes[1..4];

Wycinki jako parametry

fn sum(numbers: &[i32]) -> i32 {

println!("{}", sum(&primes[..2]));

28
5
  • Parametr &[i32] przyjmie całą tablicę, jej fragment albo Vec.

Część 2

Kolekcje

Vec, String, HashMap, iteratory i domknięcia

Vec: rozszerzalna lista

let mut scores = Vec::new();
for round in 1..=3 {
    scores.push(round * 10);
}
let mut letters = vec!['a', 'b', 'c'];
let last = letters.pop();
println!("{scores:?} {letters:?} {last:?}");
Wynik 
[10, 20, 30] ['a', 'b'] Some('c')
  • Vec<T> trzyma elementy na stercie, tak jak String: wskaźnik, długość, pojemność.
  • <T> czytamy „typu T”: Vec<i32>. Typy generyczne omówimy w rozdziale 6.
  • vec![…] tworzy Vec z elementami. push i pop wymagają mut.
  • pop zwraca Option, bo Vec może być pusty (część 4).

Odczyt elementów

println!("{}", scores[1]);
println!("{:?}", scores.get(1));
println!("{:?}", scores.get(10));
Wynik 
20
Some(20)
None
scores[10] 
index out of bounds: the len is 3 but the index is 10
  • [index] panikuje, gdy indeks jest za duży.
  • .get(index) nigdy nie panikuje. Zwraca Some(value) albo None.
  • Używaj [ ], gdy indeks na pewno jest poprawny, a .get(), gdy może nie być.

Przechodzenie i zmiana elementów

for score in &scores {
    print!("{score} ");
}
for score in &mut scores {
    *score += 1;
}
println!("{scores:?}");
Wynik 
10 20 30 [11, 21, 31]
  • for score in &scores pożycza każdy element do odczytu.
  • &mut scores pożycza każdy element do zmiany.
  • *score to dereferencja: oznacza wartość, na którą wskazuje referencja.
  • for score in scores bez & przenosi Vec do pętli i potem nie da się go użyć.

Vec a zasada pożyczania

error[E0502]: cannot borrow `numbers` as mutable because it is also borrowed as immutable
 --> src/main.rs:4:5
  |
3 |     let first = &numbers[0];
  |                  ------- immutable borrow occurs here
4 |     numbers.push(4);
  |     ^^^^^^^^^^^^^^^ mutable borrow occurs here
5 |     println!("{first}");

  • first pożycza element, a push musi zmienić cały Vec.
  • To zasada pożyczania z rozdziału 3. Następny slajd pokazuje, dlaczego jest tu ważna.

Dlaczego: push może przenieść dane

  • vec![1, 2, 3] ma miejsce na dokładnie 3 elementy.
  • push(4) rezerwuje większy bufor (pojemność 6), kopiuje elementy i zwalnia stary.
  • first wskazywałby wtedy zwolnioną pamięć. Borrow checker odrzuca to już podczas kompilacji.

String dokładniej

let mut greeting = String::from("Hello");
greeting.push(',');

  • push dodaje jeden char, a push_str dodaje &str.
  • format! buduje nowy String z kilku części.

  • Pozycja bajtu nie musi być znakiem, więc napisów nie można indeksować.
word[0]

Liczenie z entry

let sentence = "the cat and the hat";
let mut counts = HashMap::new();
for word in sentence.split_whitespace() {
    let count = counts.entry(word).or_insert(0);
    *count += 1;
}
println!("{}", counts["the"]);
Wynik 
2
  • entry(word) znajduje miejsce dla klucza.
  • .or_insert(0) wstawia tam 0, jeśli klucz jest nowy, i zwraca modyfikowalną referencję do wartości.
  • *count += 1 zmienia wartość przez tę referencję, tak jak wcześniej *score.
Część 3

Struktury

Nazwane pola, które do siebie należą

Definiowanie struktury

struct User {
    name: String,
    age: u32,
    active: bool,
}

let user = User {
    name: String::from("Alice"),
    age: 30,
    active: true,
};
println!("{} {}", user.name, user.age);
  • Struktura nazywa swoje pola i ich typy. Instancja musi ustawić każde pole.
  • Pola odczytujemy przez .name.
  • Struktura jest właścicielem pól i są one usuwane razem z nią.

Zmiana i budowanie struktur

let mut user = User {
    name: String::from("Alice"),
    age: 30,
    active: true,
};
user.age += 1;
  • Cała instancja jest mut albo nie. Pojedyncze pola nie mogą być.
  • Bez mut: E0594 cannot assign to user.age, as user is not declared as mutable.
fn new_user(name: String, age: u32) -> User {
    User {
        name,
        age,
        active: true,
    }
}
  • Skrócony zapis pól: name zamiast name: name, gdy zmienna ma nazwę pola.

Wypisywanie struktury

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

println!("{user:?}");
println!("{user:#?}");
Wynik 
User { name: "Alice", age: 30, active: true }
User {
    name: "Alice",
    age: 30,
    active: true,
}
  • #[derive(Debug)] generuje kod, dzięki któremu {:?} działa dla twojego typu.
  • Typ bez tej linii nie obsłuży {:?}, np. Meters z następnego slajdu: E0277 Meters doesn't implement Debug.
  • Działanie derive omówimy przy traitach w rozdziale 6.

Struktury krotkowe

struct Meters(f64);
struct Seconds(f64);

let distance = Meters(5.0);
let time = Seconds(2.0);
println!("{}", distance.0 / time.0);
Wynik 
2.5
  • Struktura krotkowa (tuple struct) ma nazwę, ale jej pola nie mają: .0, .1.
  • Meters i Seconds to różne typy, więc nie da się przekazać jednego zamiast drugiego, choć oba zawierają f64.

Metody

impl User {
    fn greeting(&self) -> String {
        format!("Hi, I'm {}", self.name)
    }

    fn birthday(&mut self) {
        self.age += 1;
    }
}

let mut user = User::new("Alice", 30);
user.birthday();
println!("{} ({})", user.greeting(), user.age);
Wynik 
Hi, I'm Alice (31)
  • Blok impl dodaje funkcje do typu.
  • Metoda przyjmuje self jako pierwszy parametr i wywołujemy ją z kropką: user.birthday().
  • &self pożycza do odczytu, a &mut self do zmiany, jak w rozdziale 3.

Funkcje powiązane i self

impl User {

            name: String::from(name),

            active: true,

Część 4

Enumy i Option

Wartość, która jest jednym z kilku wariantów

Enumy

enum Shape {
    Circle(f64),
    Rectangle(f64, f64),
    Empty,
}

impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle(radius) => PI * radius * radius,
            Shape::Rectangle(width, height) => width * height,
            Shape::Empty => 0.0,
        }
    }
}
  • Wartość enuma to dokładnie jeden z jego wariantów.
  • Wariant może zawierać dane, jak Circle(f64), albo nie, jak Empty.
  • match wybiera wariant i wyciąga jego dane do zmiennych.
  • Enumy też mogą mieć metody.

PI to std::f64::consts::PI.

  • Gdy dodasz wariant do enuma, każdy match, który o nim zapomina, przestaje się kompilować.

Option: wartość albo nic

enum Option<T> {
    None,
    Some(T),
}
  • Rust nie ma null. Wartość, której może brakować, ma typ Option.
  • Już go spotkaliśmy: checked_add (rozdział 2), Vec::get, pop, HashMap::get.
  • Option<i32> to nie i32. Zanim użyjesz wartości, musisz obsłużyć None.
let values = [10, 20, 30];
match values.get(5) {
    Some(value) => println!("found {value}"),
    None => println!("nothing there"),
}

nothing there

    println!("first: {first}");

  • .unwrap() daje wartość albo panikuje. Używaj go tylko wtedy, gdy None naprawdę nie może wystąpić.

Podsumowanie

  • Destrukturyzacja rozpakowuje krotki. Wycinki pożyczają fragment tablicy, Vec albo napisu.
  • Vec, String i HashMap rosną na stercie i podlegają zasadom pożyczania.
  • String to UTF-8: .len() liczy bajty, a indeksowanie jest niedozwolone.
  • Domknięcia i adaptery iteratorów przetwarzają kolekcje. Nic się nie dzieje, dopóki nie zadziała konsument.
  • Struktury grupują nazwane pola. impl dodaje metody z &self, &mut self albo self.
  • Enumy przechowują jeden z kilku wariantów. Option zastępuje null, a match musi obsłużyć każdy przypadek.
