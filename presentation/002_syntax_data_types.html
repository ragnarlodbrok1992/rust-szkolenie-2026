Part 1

Syntax basics

Anatomy of a program

fn main() {
    let greeting = "Hello";
    println!("{greeting}, Rust!");
}
Output 
Hello, Rust!
  • fn main() is a function. Its body is a block between { and }.
  • Each statement ends with ;.
  • Indent with 4 spaces. cargo fmt does it for you.
  • Line breaks and extra spaces don't change the meaning.

Naming conventions

Kind of nameConventionExamples
Variables, functionssnake_casedice_roll, print_sum
TypesUpperCamelCaseString, Vec
ConstantsSCREAMING_SNAKE_CASEMAX_POINTS (chapter 4)
The compiler checks the convention

 --> src/main.rs:2:9
  |
2 |     let diceRoll = 6;
  |         ^^^^^^^^ help: convert the identifier to snake case: `dice_roll`

Comments

// A line comment runs to the end of the line.

/* A block comment
   can span several lines. */

/// A doc comment describes the item below it.
fn main() {}
  • // is the most common kind of comment.
  • /// doc comments become documentation pages with cargo doc.

The course code has no comments. Explanations live on these slides.

Variables with let

let age = 30;
let height: f64 = 1.75;
let name = "Ferris";
  • let gives a name to a value. The name is called a variable or a binding.
  • : f64 is a type annotation. It's optional when the compiler can work out the type.
  • A variable must get a value before it's used.

Immutable by default

error[E0384]: cannot assign twice to immutable variable `age`
 --> src/main.rs:3:5
  |
2 |     let age = 30;
  |         --- first assignment to `age`
3 |     age = 31;
  |     ^^^^^^^^ cannot assign twice to immutable variable
  • Once a variable has a value, it can't be changed.
  • That makes code easier to follow: a name always means the same value.

Mutable variables (mut), constants and shadowing are covered in chapter 4.

Printing values

let age = 30;
let height = 1.75;
println!("{}", age);
println!("{age} years, {height} m");
println!("{:?}", (age, height));
Output 
30
30 years, 1.75 m
(30, 1.75)
  • {} is replaced by the next argument.
  • {age} prints the variable with that name.
  • {:?} uses the debug format. It can print tuples and arrays, which {} can't.
Part 2

Scalar types

A scalar type holds a single value

Four scalar types

Integers

Whole numbers: 42, -7, 1_000

Floating-point numbers

Numbers with a fraction: 3.14, 2.0

Booleans

Truth values: true, false

Characters

Single Unicode characters: 'a', '🦀'

Integer types

SizeSignedUnsigned
8-biti8u8
16-biti16u16
32-biti32u32
64-biti64u64
128-biti128u128
32/64-bit (platform)isizeusize
  • i types can be negative. u types can't.
  • i8: -128 to 127. u8: 0 to 255.
  • i32 is the default. Use it unless you have a reason not to.
  • usize is used for lengths and indexes.
  • Each type knows its limits: u8::MAX is 255, i8::MIN is -128.

Integer literals

LiteralWritten asValue
Decimal98_22298222
Hexadecimal0xff255
Octal0o7763
Binary0b1111_0000240
Byte (u8)b'A'65
  • _ is a visual separator. The compiler ignores it.
  • A suffix sets the type: 42u8, 1_000_i64.
  • When nothing else decides the type, an integer literal is an i32.

Floating-point numbers

let price = 2.5;
let ratio: f32 = 0.75;
println!("{}", 0.1 + 0.2);
Output 
0.30000000000000004
  • f64 (double precision) is the default.
  • f32 (single precision) uses half the memory and is less precise.
  • Many decimal fractions can't be stored exactly, so results can be slightly off.
  • Don't use floats for money.

Booleans and characters

let is_ready = true;
let has_errors: bool = false;

let letter = 'R';
let digit: char = '7';
let crab = '🦀';
  • bool is either true or false.
  • char is written in single quotes.
  • A char takes 4 bytes and holds any Unicode character: letters, digits, emoji, Chinese characters.

Single quotes vs double quotes

error[E0308]: mismatched types

  |                 ----   ^^^ expected `char`, found `&str`
  |                 |
  |                 expected due to this

help: if you meant to write a `char` literal, use single quotes
  • 'a' is a single character, of type char.
  • "a" is text, of type &str. More in part 4.
Part 3

Types in practice

Type inference

let count = 10;
let average = 2.5;
let small: u8 = 10;
let tiny = 10_u8;
  • The compiler infers types: count is an i32, average is an f64.
  • An annotation or a suffix picks a different type.
  • Rust is statically typed: every value's type is known at compile time and never changes.

Types must match

error[E0308]: mismatched types
 --> src/main.rs:2:22
  |
2 |     let whole: i32 = 3.5;
  |                ---   ^^^ expected `i32`, found floating-point number
error[E0277]: cannot add a float to an integer
 --> src/main.rs:3:19
  |
3 |     let total = 5 + 2.5;
  |                   ^ no implementation for `{integer} + {float}`
  • Rust never converts between types on its own, not even from an integer to a float. Both sides of +, -, *, / must have the same type.

Arithmetic

ExpressionResult
7 + 29
7 - 25
7 * 214
7 / 23
-7 / 2-3
7 % 21
7.0 / 2.03.5
  • Integer division drops the fraction: it truncates toward zero.
  • % gives the remainder of a division.
  • To get 3.5, divide floating-point numbers.

Converting with as

let whole = 7;
let half = whole as f64 / 2.0;
let truncated = 3.99_f64 as i32;
let big: i32 = 300;
let wrapped = big as u8;
let letter_code = 'A' as u8;
Values 
half: 3.5
truncated: 3
wrapped: 44
letter_code: 65
  • as converts between primitive types explicitly.
  • Float to integer drops the fraction.
  • Converting to a smaller integer keeps only the bits that fit: 300 becomes 44.
  • as never fails, so it can lose data silently.

Overflow

A u8 holds 0 to 255. What happens with 256?

SituationResult
let x: u8 = 256;Compile error: literal out of range for u8
let x: u8 = 255 + 1;Compile error: this arithmetic operation will overflow
Value known only at runtime, debug buildThe program stops: attempt to add with overflow
Value known only at runtime, release buildWraps around silently: 255 + 1 = 0

When a program stops like this, Rust calls it a panic.

Overflow at runtime

fn main() {
    println!("{}", add_one(255));
}

fn add_one(value: u8) -> u8 {
    value + 1
}
cargo run 
thread 'main' (38736) panicked at src/main.rs:6:5:
attempt to add with overflow
cargo run --release 
0
  • Inside add_one, the compiler doesn't know the value, so it can't report the error early.
  • Functions are covered in part 5.

Choosing what overflow does

MethodExampleResult
wrapping_add250_u8.wrapping_add(10)4: wraps around
saturating_add250_u8.saturating_add(10)255: stops at the limit
checked_add250_u8.checked_add(3)Some(253): the result fits
checked_add250_u8.checked_add(10)None: reports the overflow
  • When overflow is expected, say so explicitly with one of these methods.
  • Each one also exists for subtraction and multiplication: wrapping_sub, saturating_mul.
  • The result of checked_add is an Option, covered in chapter 5.
Part 4

Compound types

Grouping several values into one

Tuples

let person: (&str, i32, f64) = ("Alice", 30, 1.68);
println!("{}", person.0);
println!("{}", person.1);
println!("{:?}", person);
Output 
Alice
30
("Alice", 30, 1.68)
  • A tuple groups values that can have different types.
  • Its length is fixed.
  • Fields are read by position: .0, .1, .2.
  • person.3 doesn't compile: no field 3.

Unpacking a tuple into variables (destructuring) is covered in chapter 5.

Arrays

let primes = [2, 3, 5, 7, 11];
let zeros = [0; 5];
let first: i32 = primes[0];
println!("{} {}", first, primes.len());
println!("{:?}", zeros);
Output 
2 5
[0, 0, 0, 0, 0]
  • All elements have the same type.
  • The length is part of the type: primes is a [i32; 5].
  • [0; 5] is five zeros.
  • Indexes start at 0 and have the type usize.

Slices, iterating and the growable Vec are covered in chapter 5.

Index out of bounds

Index known at compile time 
error: this operation will panic at runtime
 --> src/main.rs:3:20
  |
3 |     println!("{}", primes[10]);
  |                    ^^^^^^^^^^ index out of bounds: the length is 5 but the index is 10
Index known only at runtime 
thread 'main' (10996) panicked at src/main.rs:7:20:
index out of bounds: the len is 5 but the index is 10
  • Rust always checks array indexes.
  • A bad index stops the program instead of reading memory it doesn't own, which C would allow.

String literals

let name = "Ferris";
let greeting: &str = "Hello, world!";
let initial = 'F';
  • Text in double quotes is a string literal, of type &str.
  • "F" is text. 'F' is a single char.
  • The & means a reference, covered in chapter 3.
  • Text you can build and change at runtime (String) is introduced in chapter 3 and covered in depth in chapter 5.
Part 5

Functions

Defining functions

fn main() {
    print_sum(3, 4);
}

fn print_sum(first: i32, second: i32) {
    println!("{first} + {second} = {}", first + second);
}
Output 
3 + 4 = 7
  • fn, a name, parameters in ( ), a body in { }.
  • Every parameter needs a type. Rust never infers parameter types.
  • The order of definitions in the file doesn't matter.

Returning values

Last expression 
fn square(number: i32) -> i32 {
    number * number
}
With return 
fn square(number: i32) -> i32 {
    return number * number;
}
  • -> i32 declares the return type.
  • The last expression in the body, without ;, is the return value.
  • return also works. It's mostly used to leave a function early (with if, chapter 4).
  • Both versions do the same thing. The first one is the usual style, and cargo clippy warns about the second: unneeded return statement.

Statements and expressions

let y = {
    let x = 3;
    x + 1
};
println!("{y}");
Output 
4
  • A statement does something and has no value: let x = 3;
  • An expression produces a value: 5, x + 1, a function call, a block.
  • A block's value is its last expression.
  • Adding ; turns an expression into a statement.

The unit type ()

let nothing = print_sum(3, 4);
println!("{:?}", nothing);
Output 
3 + 4 = 7
()
  • () is the empty tuple, called unit. It means "no meaningful value".
  • A function without -> returns ().
  • fn main() returns () too.

The stray semicolon

error[E0308]: mismatched types
 --> src/main.rs:5:27
  |
5 | fn square(number: i32) -> i32 {
  |    ------                 ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
6 |     number * number;
  |                    - help: remove this semicolon to return this value

The ; turns the last expression into a statement, so the body returns () instead of an i32.

Summary

  • let creates a variable. Variables are immutable by default.
  • Scalar types: integers (i32 by default), floats (f64 by default), bool, char.
  • Rust never converts types on its own. Use as, and remember it can lose data.
  • Overflow is a compile error, a panic in debug builds, or a silent wrap in release builds. Use wrapping_, saturating_ or checked_ when you expect it.
  • Tuples group different types. Arrays hold a fixed number of values of one type.
  • Functions declare parameter and return types. The last expression without ; is the return value.

  • Zły indeks zatrzymuje program, zamiast czytać nie swoją pamięć, na co pozwoliłoby C.

Literały napisowe

let name = "Ferris";
let greeting: &str = "Hello, world!";
let initial = 'F';
  • Tekst w cudzysłowach to literał napisowy, typu &str.
  • "F" to tekst. 'F' to pojedynczy char.
  • & oznacza referencję, omówioną w rozdziale 3.
  • Tekst, który można budować i zmieniać w czasie działania (String), poznamy w rozdziale 3, a dokładnie omówimy w rozdziale 5.
Część 5

Funkcje

Definiowanie funkcji

fn main() {
    print_sum(3, 4);
}

fn print_sum(first: i32, second: i32) {
    println!("{first} + {second} = {}", first + second);
}
Wynik 
3 + 4 = 7
  • fn, nazwa, parametry w ( ), ciało w { }.
  • Każdy parametr musi mieć typ. Rust nigdy nie wnioskuje typów parametrów.
  • Kolejność definicji w pliku nie ma znaczenia.

Zwracanie wartości

Ostatnie wyrażenie 
fn square(number: i32) -> i32 {
    number * number
}
Z return 
fn square(number: i32) -> i32 {
    return number * number;
}
  • -> i32 deklaruje typ zwracanej wartości.
  • Ostatnie wyrażenie w ciele, bez ;, jest zwracaną wartością.
  • return też działa. Używa się go głównie do wcześniejszego wyjścia z funkcji (z if, rozdział 4).
  • Obie wersje robią to samo. Pierwsza to zwykły styl, a cargo clippy ostrzega przy drugiej: unneeded return statement.

Instrukcje i wyrażenia

let y = {
    let x = 3;
    x + 1
};
println!("{y}");
Wynik 
4
  • Instrukcja coś wykonuje i nie ma wartości: let x = 3;
  • Wyrażenie daje wartość: 5, x + 1, wywołanie funkcji, blok.
  • Wartością bloku jest jego ostatnie wyrażenie.
  • Dodanie ; zamienia wyrażenie w instrukcję.

Typ jednostkowy ()

let nothing = print_sum(3, 4);
println!("{:?}", nothing);
Wynik 
3 + 4 = 7
()
  • () to pusta krotka, nazywana unit. Oznacza „brak znaczącej wartości”.
  • Funkcja bez -> zwraca ().
  • fn main() też zwraca ().

Zbędny średnik

error[E0308]: mismatched types
 --> src/main.rs:5:27
  |
5 | fn square(number: i32) -> i32 {
  |    ------                 ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
6 |     number * number;
  |                    - help: remove this semicolon to return this value

Znak ; zamienia ostatnie wyrażenie w instrukcję, więc ciało zwraca () zamiast i32.

Podsumowanie

  • let tworzy zmienną. Zmienne są domyślnie niezmienne.
  • Typy skalarne: liczby całkowite (domyślnie i32), zmiennoprzecinkowe (domyślnie f64), bool, char.
  • Rust nigdy sam nie zamienia typów. Używaj as i pamiętaj, że może gubić dane.
  • Przepełnienie to błąd kompilacji, panika w wersji debug albo ciche zawinięcie w wersji release. Gdy się go spodziewasz, użyj wrapping_, saturating_ albo checked_.
  • Krotki grupują różne typy. Tablice mieszczą stałą liczbę wartości jednego typu.
  • Funkcje deklarują typy parametrów i zwracanej wartości. Ostatnie wyrażenie bez ; jest zwracaną wartością.

Dalej: rozdział 3, własność i referencje.
