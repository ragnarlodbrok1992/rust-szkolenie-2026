Part 1

Ownership

Who frees the memory, and when?

Who frees the memory?

Manually: C, C++

The programmer frees memory. Forget it and memory leaks. Free it twice, or use it after freeing, and the program crashes or worse.

A garbage collector: Java, Python, Go

A runtime finds unused memory and frees it. Safe, but it costs time and memory while the program runs.

Ownership: Rust

The compiler knows when each value is no longer needed and inserts the cleanup there. Safe, with no runtime cost.

Stack and heap

let number = 5;
let text = String::from("hello");
  • Stack: values with a fixed size known at compile time, like all the types from chapter 2. Freed automatically when the function ends.
  • Heap: data whose size is known only at runtime, or that can grow. Has to be freed exactly once.
  • Ownership is how Rust decides when heap data is freed.

String: text on the heap

let literal: &str = "hello";
let mut owned = String::from("hello");
owned.push_str(", world");
println!("{literal} / {owned} / {}", owned.len());
Output 
hello / hello, world / 12
  • String::from creates text that the variable owns.
  • push_str appends text. The String grows on the heap.
  • let mut allows the variable to change. Mutability is covered in chapter 4.

&str vs String

Can grow or changeNoYes, with mut

  • A &String can be passed where a &str is expected. You'll see this in part 2.

The rest of String is covered in chapter 5.

The ownership rules

  1. Each value has an owner.
  2. There is only one owner at a time.
  3. When the owner goes out of scope, the value is dropped.
{
    let text = String::from("hello");
    println!("{text}");
}
  • text is valid from let to the closing }.
  • At } Rust drops text and frees its heap memory.
  • Using text after } fails: cannot find value text in this scope.

Move

let first = String::from("hello");
let second = first;
println!("{second}");
  • let second = first; copies only the pointer, length and capacity. The text on the heap isn't copied.
  • Ownership moves to second, and first can't be used anymore.
  • Otherwise both would free the same memory at }.

Using a moved value

error[E0382]: borrow of moved value: `first`
 --> src/main.rs:4:16

  |         ----- move occurs because `first` has type `String`, which does not implement the `Copy` trait
3 |     let second = first;
  |                  ----- value moved here
4 |     println!("{first} {second}");
  |                ^^^^^ value borrowed here after move

help: consider cloning the value if the performance cost is acceptable
  |
3 |     let second = first.clone();
  |                       ++++++++
  • The compiler shows where the value was moved and where it's used afterwards.
  • It also suggests a fix: .clone().

Copy and clone

Copy 
let x = 5;
let y = x;
println!("{x} {y}");
  • Values that live only on the stack are copied, and both variables stay usable.
  • Copy types: integers, floats, bool, char, and tuples and arrays made of them.
Clone 
let original = String::from("hello");
let copy = original.clone();
println!("{original} {copy}");
  • .clone() copies the heap data too, so both variables own their own text.
  • It can be expensive, so Rust makes you write it out.

Ownership and functions

fn main() {
    let text = String::from("hello");
    take_ownership(text);
    let returned = give_back(String::from("hi"));
    println!("{returned}");
}

fn take_ownership(value: String) {
    println!("{value}");
}

fn give_back(value: String) -> String {
    value
}
  • Passing a String to a function moves it into the parameter.
  • value is dropped at the end of take_ownership. Using text afterwards fails with E0382.
  • Returning a value moves ownership back to the caller.
  • Copy types such as i32 are copied into the function.
  • Passing ownership back and forth gets tedious. References solve that.
Part 2

References and borrowing

Using a value without taking ownership

References

let text = String::from("hello");
let borrowed = &text;
println!("{borrowed} {text}");
  • &text creates a reference: it points to the value without owning it.
  • Creating a reference is called borrowing.
  • text stays the owner and is still usable.
  • When borrowed goes out of scope, nothing is freed.

Borrowing in functions

fn main() {
    let text = String::from("hello");
    let length = length_of(&text);
    println!("{text} has {length} bytes");
}

fn length_of(value: &str) -> usize {
    value.len()
}
Output 
hello has 5 bytes
  • The function borrows the text, and ownership stays in main.
  • &text is a &String, passed where a &str is expected.
  • A &str parameter accepts both string literals and borrowed Strings.

References are read-only

error[E0596]: cannot borrow `*value` as mutable, as it is behind a `&` reference
 --> src/main.rs:7:5
  |
7 |     value.push_str(", world");
  |     ^^^^^ `value` is a `&` reference, so the data it refers to cannot be borrowed as mutable
  |
help: consider changing this to be a mutable reference
  |
6 | fn add_world(value: &mut String) {
  |                      +++
  • A & reference can only read the value.
  • To change a borrowed value, you need a mutable reference: &mut.

Mutable references

fn main() {
    let mut text = String::from("hello");
    add_world(&mut text);
    println!("{text}");
}

fn add_world(value: &mut String) {
    value.push_str(", world");
}
Output 
hello, world
  • &mut borrows with permission to change the value.
  • The variable must be declared with let mut too.
  • The caller sees the change, and ownership never left main.

The borrowing rule

At any time, a value can have either any number of & references or exactly one &mut reference.

Borrows, then both usedResult
let a = &text; let b = &text;Compiles: many readers are fine
let a = &mut text; let b = &mut text;E0499: cannot borrow text as mutable more than once at a time
let a = &text; let b = &mut text;E0502: cannot borrow text as mutable because it is also borrowed as immutable

Nobody can change a value while someone else is reading it. That rules out data races at compile time.

A borrow ends at its last use

let mut text = String::from("hello");
let reader = &text;
println!("{reader}");
let writer = &mut text;
writer.push_str(", world");
println!("{text}");
Output 
hello
hello, world
  • A borrow lasts until the reference is used for the last time, not until }.
  • reader is done after the first println!, so writer is allowed.
  • The order of uses matters, not where the variables are declared.

The borrow checker

error[E0499]: cannot borrow `text` as mutable more than once at a time
 --> src/main.rs:4:18
  |
3 |     let first = &mut text;
  |                 --------- first mutable borrow occurs here
4 |     let second = &mut text;
  |                  ^^^^^^^^^ second mutable borrow occurs here
5 |     println!("{first} {second}");
  |                ----- first borrow later used here
  • The borrow checker is the part of the compiler that enforces these rules.
  • It guarantees no use after a move, no dangling references and no data races, with no runtime cost.
  • Its errors point to both borrows and to the later use. Fix it by finishing one borrow before starting the other.

Dangling references

fn make_greeting() -> &String {
    let greeting = String::from("hello");
    &greeting
}
error[E0106]: missing lifetime specifier
 --> src/main.rs:5:23
  |
5 | fn make_greeting() -> &String {
  |                       ^ expected named lifetime parameter
  |
  = help: this function's return type contains a borrowed value, but there is no value for it to be borrowed from
help: instead, you are more likely to want to return an owned value
  • greeting is dropped when the function ends, so the reference would point to freed memory. The fix: return the String itself.
Part 3

Lifetimes

How long a reference stays valid

Does not live long enough

error[E0597]: `text` does not live long enough
 --> src/main.rs:5:21
  |
4 |         let text = String::from("hello");
  |             ---- binding `text` declared here
5 |         reference = &text;
  |                     ^^^^^ borrowed value does not live long enough
6 |     }
  |     - `text` dropped here while still borrowed
7 |     println!("{reference}");
  |                --------- borrow later used here
  • A lifetime is the part of the program where a reference is valid.
  • A reference must never outlive the value it points to.
  • The compiler checks this for every reference.

When the compiler needs help

fn longer(first: &str, second: &str) -> &str {
    if first.len() >= second.len() {
        first
    } else {
        second
    }
}
error[E0106]: missing lifetime specifier
 --> src/main.rs:5:41
  |
5 | fn longer(first: &str, second: &str) -> &str {
  |                  ----          ----     ^ expected named lifetime parameter
  • The result is either first or second. The if decides at runtime (if is covered in chapter 4).
  • The signature doesn't say which input the result borrows from.
  • So the compiler can't check how long the result stays valid.

Lifetime annotations

fn longer<'a>(first: &'a str, second: &'a str) -> &'a str {
    if first.len() >= second.len() {
        first
    } else {
        second
    }
}
  • <'a> declares a lifetime named 'a. Lifetime names start with '.
  • It reads: the result is valid as long as both inputs are still valid.
  • Annotations don't change how long values live. They describe how references relate, so the compiler can check them.

Lifetimes in action

error[E0597]: `inner` does not live long enough
 --> src/main.rs:6:33
  |
5 |         let inner = String::from("short");
  |             ----- binding `inner` declared here
6 |         result = longer(&outer, &inner);
  |                                 ^^^^^^ borrowed value does not live long enough
7 |     }
  |     - `inner` dropped here while still borrowed
8 |     println!("{result}");
  |                ------ borrow later used here
  • By the signature, result may point to inner, which is dropped at }.
  • The compiler checks the signature, not which value is longer at runtime.

Elision and 'static

Lifetime elision 
fn trimmed(text: &str) -> &str {
    text.trim()
}
  • With one reference parameter, the compiler assumes the result borrows from it.
  • You only write lifetimes when the compiler can't work them out.
'static 
let greeting: &'static str = "hello";
  • 'static means valid for the whole run of the program.
  • String literals are stored in the program binary, so every literal is a &'static str.

Lifetimes in structs are covered in chapter 5.

Summary

  • Every value has exactly one owner, and it's dropped when the owner goes out of scope.
  • Assigning or passing a String moves it. Copy types are copied. .clone() copies explicitly.
  • & borrows to read, and &mut borrows to change. Either many & or one &mut at a time.
  • A borrow ends at its last use.
  • A reference can't outlive its value. Lifetime annotations describe how references relate.
  • The borrow checker enforces all of this at compile time.

Część 1

Własność

Kto zwalnia pamięć i kiedy?

Kto zwalnia pamięć?

Ręcznie: C, C++

Pamięć zwalnia programista. Zapomni, a pamięć wycieka. Zwolni dwa razy albo użyje po zwolnieniu, a program się wysypie albo stanie się coś gorszego.

Garbage collector: Java, Python, Go

Środowisko uruchomieniowe znajduje nieużywaną pamięć i ją zwalnia. Bezpiecznie, ale kosztem czasu i pamięci w trakcie działania programu.

Własność: Rust

Kompilator wie, kiedy każda wartość przestaje być potrzebna, i właśnie tam wstawia jej sprzątanie. Bezpiecznie i bez kosztów w czasie działania.

Stos i sterta

let number = 5;
let text = String::from("hello");
  • Stos (stack): wartości o stałym rozmiarze znanym w czasie kompilacji, jak wszystkie typy z rozdziału 2. Zwalniane automatycznie, gdy funkcja się kończy.
  • Sterta (heap): dane, których rozmiar jest znany dopiero w czasie działania albo które mogą rosnąć. Trzeba je zwolnić dokładnie raz.
  • Własność to sposób, w jaki Rust decyduje, kiedy zwolnić dane na stercie.

String: tekst na stercie

let literal: &str = "hello";
let mut owned = String::from("hello");
owned.push_str(", world");
println!("{literal} / {owned} / {}", owned.len());
Wynik 
hello / hello, world / 12
  • String::from tworzy tekst, którego zmienna jest właścicielem.
  • push_str dopisuje tekst. String rośnie na stercie.
  • let mut pozwala zmieniać zmienną. Modyfikowalność omówimy w rozdziale 4.

&str a String

  • &String można przekazać tam, gdzie oczekiwany jest &str. Zobaczymy to w części 2.

Resztę o String omówimy w rozdziale 5.

Zasady własności

  1. Każda wartość ma właściciela.
  2. W danej chwili jest tylko jeden właściciel.
  3. Gdy właściciel wychodzi z zasięgu, wartość jest usuwana (drop).
{
    let text = String::from("hello");
    println!("{text}");
}
  • text jest dostępne od let do zamykającego }.
  • Przy } Rust usuwa text i zwalnia jego pamięć na stercie.
  • Użycie text po } kończy się błędem: cannot find value text in this scope.

Przeniesienie (move)

let first = String::from("hello");
let second = first;
println!("{second}");
  • let second = first; kopiuje tylko wskaźnik, długość i pojemność. Tekst na stercie nie jest kopiowany.
  • Własność przechodzi na second, a first nie nadaje się już do użycia.
  • W przeciwnym razie obie zmienne zwolniłyby tę samą pamięć przy }.

Użycie przeniesionej wartości

  • Kompilator pokazuje, gdzie wartość została przeniesiona i gdzie jest użyta potem.
  • Podpowiada też poprawkę: .clone().

Kopiowanie i klonowanie

Copy 
let x = 5;
let y = x;
println!("{x} {y}");
  • Wartości, które żyją tylko na stosie, są kopiowane, a obie zmienne zostają do użycia.
  • Typy Copy: liczby całkowite i zmiennoprzecinkowe, bool, char oraz zbudowane z nich krotki i tablice.
Clone 
let original = String::from("hello");
let copy = original.clone();
println!("{original} {copy}");
  • .clone() kopiuje też dane ze sterty, więc każda zmienna ma własny tekst.
  • To może być kosztowne, dlatego Rust każe zapisać to jawnie.

Własność a funkcje

fn main() {
    let text = String::from("hello");
    take_ownership(text);
    let returned = give_back(String::from("hi"));
    println!("{returned}");
}

fn take_ownership(value: String) {
    println!("{value}");
}

fn give_back(value: String) -> String {
    value
}
  • Przekazanie String do funkcji przenosi go do parametru.
  • value jest usuwane na końcu take_ownership. Późniejsze użycie text kończy się błędem E0382.
  • Zwrócenie wartości przenosi własność z powrotem do wywołującego.
  • Typy Copy, takie jak i32, są do funkcji kopiowane.
  • Przekazywanie własności tam i z powrotem jest uciążliwe. Rozwiązaniem są referencje.
Część 2

Referencje i pożyczanie

Używanie wartości bez przejmowania własności

Referencje

let text = String::from("hello");
let borrowed = &text;
println!("{borrowed} {text}");
  • &text tworzy referencję: wskazuje wartość, ale nie jest jej właścicielem.
  • Tworzenie referencji nazywamy pożyczaniem (borrowing).
  • text pozostaje właścicielem i dalej można go używać.
  • Gdy borrowed wychodzi z zasięgu, nic nie jest zwalniane.

Pożyczanie w funkcjach

fn main() {
    let text = String::from("hello");
    let length = length_of(&text);
    println!("{text} has {length} bytes");
}

fn length_of(value: &str) -> usize {
    value.len()
}
Wynik 
hello has 5 bytes
  • Funkcja pożycza tekst, a własność zostaje w main.
  • &text to &String, przekazany tam, gdzie oczekiwany jest &str.
  • Parametr &str przyjmuje zarówno literały, jak i pożyczone Stringi.

Referencje są tylko do odczytu

  • Referencja & pozwala tylko odczytać wartość.
  • Żeby zmienić pożyczoną wartość, potrzebna jest referencja modyfikowalna: &mut.

Referencje modyfikowalne

fn main() {
    let mut text = String::from("hello");
    add_world(&mut text);
    println!("{text}");
}

    value.push_str(", world");
}
Wynik 
hello, world
  • &mut pożycza z prawem do zmiany wartości.
  • Zmienna też musi być zadeklarowana jako let mut.
  • Wywołujący widzi zmianę, a własność nigdy nie opuściła main.

Zasada pożyczania

W danej chwili wartość może mieć albo dowolnie wiele referencji &, albo dokładnie jedną referencję &mut.

Pożyczenia, potem użycie obuWynik

Pożyczenie kończy się przy ostatnim użyciu

  • reader kończy pracę po pierwszym println!, więc writer jest dozwolony.
  • Liczy się kolejność użyć, a nie miejsce deklaracji zmiennych.

Borrow checker

Część 3

Czasy życia

Jak długo referencja pozostaje ważna

Wartość żyje za krótko

error[E0597]: `text` does not live long enough
 --> src/main.rs:5:21
  |
4 |         let text = String::from("hello");
  |             ---- binding `text` declared here
5 |         reference = &text;
  |                     ^^^^^ borrowed value does not live long enough
6 |     }
  |     - `text` dropped here while still borrowed
7 |     println!("{reference}");
  |                --------- borrow later used here
  • Czas życia (lifetime) to fragment programu, w którym referencja jest ważna.
  • Referencja nigdy nie może żyć dłużej niż wartość, którą wskazuje.
  • Kompilator sprawdza to dla każdej referencji.

Kiedy kompilator potrzebuje pomocy

fn longer(first: &str, second: &str) -> &str {
    if first.len() >= second.len() {
        first
    } else {
        second
    }
}
error[E0106]: missing lifetime specifier
 --> src/main.rs:5:41
  |
5 | fn longer(first: &str, second: &str) -> &str {
  |                  ----          ----     ^ expected named lifetime parameter
  • Wynikiem jest first albo second. Decyduje o tym if w czasie działania (if omówimy w rozdziale 4).
  • Sygnatura nie mówi, od którego argumentu wynik jest pożyczony.
  • Kompilator nie może więc sprawdzić, jak długo wynik jest ważny.

Adnotacje czasu życia

fn longer<'a>(first: &'a str, second: &'a str) -> &'a str {
    if first.len() >= second.len() {
        first
    } else {
        second
    }
}
  • <'a> deklaruje czas życia o nazwie 'a. Nazwy czasów życia zaczynają się od '.
  • Czytamy to tak: wynik jest ważny, dopóki oba argumenty są ważne.
  • Adnotacje nie zmieniają tego, jak długo żyją wartości. Opisują zależności między referencjami, żeby kompilator mógł je sprawdzić.

Czasy życia w praktyce

  • Kompilator sprawdza sygnaturę, a nie to, która wartość jest dłuższa w czasie działania.

Pomijanie czasów życia i 'static

Pomijanie (elision) 
fn trimmed(text: &str) -> &str {
    text.trim()
}
  • Przy jednym parametrze-referencji kompilator zakłada, że wynik jest pożyczony od niego.
  • Czasy życia zapisujesz tylko wtedy, gdy kompilator sam ich nie ustali.
'static 
let greeting: &'static str = "hello";
  • 'static oznacza: ważne przez cały czas działania programu.
  • Literały napisowe są zapisane w pliku programu, więc każdy literał to &'static str.

Czasy życia w strukturach omówimy w rozdziale 5.

Podsumowanie

  • Każda wartość ma dokładnie jednego właściciela i jest usuwana, gdy właściciel wychodzi z zasięgu.
  • Przypisanie lub przekazanie String go przenosi. Typy Copy są kopiowane. .clone() kopiuje jawnie.
  • & pożycza do odczytu, a &mut do zmiany. W danej chwili albo wiele &, albo jedna &mut.
  • Pożyczenie kończy się przy ostatnim użyciu.
  • Referencja nie może żyć dłużej niż jej wartość. Adnotacje czasu życia opisują zależności między referencjami.
  • Borrow checker pilnuje tego wszystkiego podczas kompilacji.

Dalej: rozdział 4, zmienne, sterowanie przepływem i makra.
